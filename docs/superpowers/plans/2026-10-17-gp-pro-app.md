# GP Pro (app Flutter) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remplacer Kilo Pro par GP Pro dans l'app : demande depuis l'onglet Moi et l'inscription, écran de statut `/profile/gp-pro`, badge `GpProBadge` partout où un voyageur est présenté, filtre « GP Pro ».

**Architecture:** Nouvelle feature `lib/features/gp_pro/` (`bloc/` + `data/` + `presentation/`) qui parle à `/gp-pro/**` (yadony-back#560). Un widget de design system `GpProBadge` lu depuis des champs `gpPro` ajoutés aux modèles existants, tous `false` par défaut (back ancien toléré). Le filtre `kiloProOnly` est renommé `gpProOnly` de bout en bout.

**Tech Stack:** Flutter, flutter_bloc (Cubit), GoRouter, Dio via `ApiClient`, GetIt, json_serializable (seulement `TravelerProfile`), mocktail + bloc_test, ARB FR/EN.

**Spec:** `docs/superpowers/specs/2026-10-17-gp-pro-design.md` (§7.2, §7.8, §7.9, §7.10, §7.12). Contrat back : description de MONDONY/yadony-back#560.

## Global Constraints

- Nom public « GP Pro », identique en FR et EN. Jamais « Kilo Pro » ni « Dony » visible.
- À la fin : `git grep -n -i "kilo.\?pro" -- lib test` ne renvoie rien (hors `trip_leg_draft.dart` / `trip_leg_sheet.dart`, où « prix au kilo propre » n'est pas Kilo Pro). Clé ARB `listingKiloProChip` supprimée.
- Tout champ GP Pro lu avec `false` par défaut si absent ; tout appel `/gp-pro/**` qui échoue en 404 (back ancien) ne casse aucun parcours.
- Contrat back (yadony-back#560) :
  - `GET /gp-pro/me` → `{state, travelFrequency?, commercialName?, documentCount, reason?, decidedAt?}` ; `state` ∈ `NONE, AWAITING_KYC, PENDING, ACTIVE, REJECTED, REVOKED`. Champ optionnel futur `documents: [{id, type}]` : le lire s'il existe.
  - `POST /gp-pro/applications` body `{travelFrequency, commercialName?, documentIds?, source}` (`source` ∈ `SIGNUP`, `PROFILE`) → 201 même forme que `/me`. Erreurs : 409 `gp-pro-already-active`, 409 `gp-pro-application-open`, 422 `gp-pro-kyc-required` (PROFILE sans KYC), 422 `gp-pro-document-invalid`.
  - `POST /gp-pro/documents` multipart `file` + `type` (`BUSINESS_REGISTRATION`, `TRAVEL_PROOF`, `SOCIAL_PROFILE`, `OTHER`) → 201 `{documentId, type}`. Images seules, 5 Mo, 4 au plus (422 `gp-pro-too-many-documents`).
  - `POST /gp-pro/applications/current/documents` body `{documentIds}` → statut ; `DELETE /gp-pro/documents/{id}` → 204 (503 `gp-pro-document-storage-unavailable`) ; `DELETE /gp-pro/applications/current` → 204 (404 `gp-pro-application-not-found`).
  - Champs ajoutés : `TravelerProfile.gpPro`, `BidModel.senderGpPro`/`travelerGpPro`, `ProfilePublicModel.gpPro` (clé JSON `gpPro`), `ParticipantModel.gpPro`, `SenderPublicProfile.gpPro`, `NegotiationThread.travelerGpPro`/`senderGpPro`. `BidNegotiation.counterpartyGpPro` n'existe pas encore côté back : lu s'il arrive, `false` sinon.
  - `/search/parse` : lire `filters['gpProOnly'] ?? filters['kiloProOnly']`. Paramètre de recherche envoyé : `gpProOnly`.
  - Notifications `GP_PRO_APPROVED`, `GP_PRO_REJECTED`, `GP_PRO_REVOKED`, deeplink `profile/gp-pro`.
- Valeurs : fréquences `WEEKLY`, `TWICE_A_MONTH`, `MONTHLY`, `LESS_OFTEN` ; nom commercial 80 caractères max ; 4 justificatifs max ; images seules (`DonyMediaService.pick`), 5 Mo max.
- Copie FR fixée par le spec : « Je suis GP (voyageur régulier ou entreprise) », « Devenir GP Pro », « En cours d'examen », « Votre demande partira dès que votre identité sera vérifiée », « Refaire une demande », « Vos documents servent uniquement à examiner votre demande. Ils sont supprimés dès que nous avons décidé. »
- Règles projet : `context.l10n` pour tout texte (garde-fou `tool/check_hardcoded_strings.dart` à 0), pas de `setState`, GoRouter seulement, `DonyButton` des feuilles dans `stickyBottom`, pas de dégradé, pas d'icône camion, `unawaited(_analytics.logEvent(...))` dans les cubits, `AnalyticsService` injecté dans tout cubit, aucune PII (jamais le nom commercial), pas de code mort.
- Après tout ajout de clé ARB : `flutter gen-l10n` puis `dart run tool/gen_l10n_catalog.dart` (le catalogue couvre les nouvelles lignes).
- Couverture CI globale ≥ 90 % : chaque fichier nouveau ou touché a ses tests.

### Task 6: `GpProCubit` (statut, formulaire, justificatifs, annulation)

**Files:**
- Create: `lib/features/gp_pro/bloc/gp_pro_cubit.dart`, `lib/features/gp_pro/bloc/gp_pro_state.dart`
- Modify: `lib/core/di/injection.dart` (`registerFactory(() => GpProCubit(getIt(), getIt<AnalyticsService>()))`)
- Test: `test/features/gp_pro/bloc/gp_pro_cubit_test.dart`

**Interfaces:**
- Consumes: `GpProRepository`, modèles et exceptions de Task 1, `AnalyticsEvents` de Task 2.
- Produces:
  - `enum GpProLoadStatus { loading, ready, failure, unavailable }`
  - `enum GpProUploadStatus { uploading, ready, failed }`
  - `class GpProPiece extends Equatable { final String localId; final GpProDocType type; final String? localPath; final String? remoteId; final GpProUploadStatus status; }` — une pièce affichée ; `localPath == null` pour une pièce venue de `status.documents`.
  - `class GpProCubitState extends Equatable { final GpProLoadStatus load; final GpProStatus? status; final GpProFrequency? frequency; final List<GpProPiece> pieces; final bool submitting; final bool cancelling; final bool restarting; final String? errorCode; bool get canAddPiece => pieces.length < 4; bool get hasUploading; bool get canSubmit => frequency != null && !hasUploading && !submitting; }`
  - `GpProCubit(GpProRepository, AnalyticsService)` :
    - `Future<void> load()` — `fetchStatus` ; `GpProUnavailableException` → `unavailable` ; autre erreur → `failure`. Au premier `ready`, log `gp_pro_application_opened` `{status: state.wire}` une seule fois par instance. Si `status.documents != null`, `pieces` en est construit (status `ready`).
    - `void selectFrequency(GpProFrequency)`.
    - `Future<void> addPiece({required String filePath, required GpProDocType type})` — refuse si `!canAddPiece` ; pièce `uploading` → `uploadDocument` → si `status.isOpen`, `attachDocuments([id])` puis remplace `status` par la réponse ; pièce `ready` + log `gp_pro_document_added` `{doc_type: type.wire}` ; erreur → pièce `failed`, `errorCode`.
    - `Future<void> removePiece(String localId)` — pièce `failed` ou sans `remoteId` : retirée localement, sans appel. Sinon `removeDocument(remoteId)` ; succès → retirée + log `gp_pro_document_removed` `{doc_type}` ; erreur (dont 503) → pièce gardée, `errorCode`.
    - `Future<void> submit({String? commercialName})` — si `!canSubmit` rien ; `apply(source: profile, documentIds: remoteIds des pièces ready)` ; succès → `status` = réponse, `pieces` gardées (désormais rattachées), log `gp_pro_application_submitted` `{source: 'profile', frequency: wire, document_count, has_commercial_name}` (jamais le nom) ; 409 (`gp-pro-application-open` / `gp-pro-already-active`) → `load()` ; autre erreur → `errorCode`.
